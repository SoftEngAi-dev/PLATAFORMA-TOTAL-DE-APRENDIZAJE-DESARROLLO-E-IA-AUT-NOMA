# Biblioteca y marcos mentales v0.1

Esta selección acompaña las especificaciones del documento maestro: aprender
haciendo, construir proyectos, comprender antes de automatizar, evaluar con
evidencia y desarrollar autonomía con supervisión humana.

## Cómo leer dentro de la plataforma

No se copiarán libros protegidos ni se presentarán resúmenes como sustituto de
las obras. La plataforma usará ideas breves, preguntas, ejercicios y
referencias para que el estudiante consulte la fuente legítima.

Cada lectura sigue este ciclo:

```text
Idea → ejemplo propio → práctica → evidencia → reflexión → transferencia al proyecto
```

## Estudiar rápido y fácil, sin estudiar superficialmente

“Rápido” significa reducir desperdicio, no eliminar esfuerzo. Para cada sesión:

1. **Define un resultado observable**: “puedo explicar y probar X”.
2. **Haz un mapa de 5 minutos**: conceptos, prerequisitos y una pregunta.
3. **Estudia en bloques de 25–50 minutos** sin cambiar de tarea.
4. **Cierra el material y recupera**: escribe o explica lo que recuerdas.
5. **Construye un ejemplo pequeño** y modifica una variable.
6. **Comprueba con una prueba o criterio de éxito**.
7. **Espacia el repaso**: hoy, mañana, en tres días y en una semana.
8. **Registra el error**: qué esperaba, qué ocurrió y qué cambiaré.

La plataforma debe medir evidencia y transferencia al proyecto, no únicamente
tiempo conectado o páginas completadas.

## Manifestación: traducción operativa y límites

La palabra “manifestación” se puede usar de forma segura si significa convertir
una intención en conducta observable. No se presentará como una ley física ni
como garantía de que imaginar algo lo vuelve real.

El método recomendado es **WOOP**:

- **Wish**: deseo concreto y alcanzable.
- **Outcome**: resultado que se podrá observar.
- **Obstacle**: obstáculo interno o situacional más probable.
- **Plan**: intención de implementación: “si ocurre X, haré Y”.

Ejemplo para el curso:

```text
Deseo: terminar el módulo de APIs.
Resultado: una ruta GET y una POST con pruebas.
Obstáculo: cambiar de tarea cuando aparece un error.
Plan: si me bloqueo, reduzco el caso a un JSON mínimo y registro el error.
```

WOOP se presenta como una estrategia de metas basada en investigación, no como
promesa sobrenatural. La visualización de proceso y obstáculos es preferible a
imaginar únicamente un resultado positivo.

## Estoicismo aplicado con cuidado

El estoicismo es una escuela filosófica antigua, no una técnica de negar
emociones ni de tolerar abusos. Para el producto aporta:

- distinguir lo que depende de mí de lo que no;
- examinar juicios antes de reaccionar;
- practicar virtud, responsabilidad y servicio;
- aceptar incertidumbre sin abandonar la acción;
- revisar el día y aprender de los errores.

En un proyecto: el estudiante no controla que una API externa esté disponible,
pero sí controla el diseño de un fallback, el registro del fallo y la prueba
que hará después. Se deben estudiar fuentes y traducciones legítimas de
Epicteto, Séneca y Marco Aurelio, junto con contexto histórico.

## La familia de “-ismos” y su uso educativo

No son sinónimos ni una jerarquía única. Son lentes que deben contrastarse:

| Corriente | Pregunta útil | Uso en la plataforma | Precaución |
| --- | --- | --- | --- |
| Empirismo | ¿Qué observación o prueba lo respalda? | Tests, experimentos y evidencia | Los datos requieren interpretación |
| Racionalismo | ¿Qué se deduce de las premisas? | Algoritmos, lógica y modelos | Una deducción no valida premisas falsas |
| Pragmatismo | ¿Qué funciona para este objetivo y contexto? | Prototipos, feedback y trade-offs | “Funciona” no significa ético o sostenible |
| Constructivismo | ¿Qué construye el estudiante a partir de su experiencia? | Proyectos, andamiaje y reflexión | No sustituye instrucción explícita cuando hace falta |
| Cognitivismo | ¿Cómo se procesa y recupera la información? | Chunks, memoria, práctica espaciada | Evitar convertir modelos en recetas universales |
| Humanismo | ¿Qué necesita la persona para crecer con dignidad? | Agencia, accesibilidad y tutoría | No confundir motivación con ausencia de exigencia |
| Existencialismo | ¿Qué responsabilidad y sentido asumo? | Propósito del proyecto y decisiones | No usarlo para romantizar aislamiento o angustia |
| Minimalismo | ¿Qué puedo quitar sin perder valor? | Interfaces simples, foco y menor carga cognitiva | No eliminar controles necesarios |
| Estoicismo | ¿Qué depende de mí y cómo actúo virtuosamente? | Resiliencia, revisión y responsabilidad | No reprimir emociones ni normalizar daño |

La rama que abarca el conjunto puede describirse como **filosofía práctica y
epistemología aplicada al aprendizaje**: cómo conocemos, cómo actuamos y cómo
convertimos conocimiento en decisiones verificables.
